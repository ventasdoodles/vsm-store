# CONTEXTO MAESTRO, BASE OPERATIVA Y HANDOFF CANONICO

## Rol de este documento
Este archivo define la base operativa del sistema de trabajo.
No guarda estado temporal del chat.
No reemplaza reglas inmutables ni plantillas.

## Modelo operativo autoritativo
- Codex audita, clasifica, acepta o rechaza.
- Antigravity implementa, corrige, ejecuta cambios y passes operativos autorizados.
- ChatGPT orquesta, sintetiza y redacta prompts.
- Gemini solo consulta cuando el problema pertenece al ecosistema Google AI / Gemini.
- El usuario define vision, aprobacion direccional y criterio final.

## Fronteras de rol
### Codex
- audita
- hace acceptance audit
- encuentra riesgos, regresiones y falta de evidencia
- no implementa cuando el prompt es de auditoria

### Antigravity
- implementa cambios autorizados
- ejecuta scripts, migraciones y operaciones locales autorizadas
- no redefine el plan estrategico por encima del prompt vigente

### ChatGPT
- decide secuencia
- elige la siguiente herramienta correcta
- traduce hallazgos en prompts accionables
- no reescribe el canon del producto fuera del scope autorizado

### Gemini
- consulta puntual de SDKs, modelos o integraciones Google AI
- no se usa como autoridad general del proyecto
- no desplaza a Codex, Antigravity ni ChatGPT

## Regla Google-first para Gemini
- Para detalles de implementacion de Gemini, Google AI o Vertex AI, la autoridad tecnica primaria son la documentacion oficial y recomendaciones vigentes de Google.
- Esta regla aplica a arquitectura y mejores practicas del plano de integracion Gemini: request shape, SDK/API, `generationConfig`, `response_mime_type`, `response_schema`, structured output, function calling/tools, seleccion de modelo, limites del proveedor y compatibilidad.
- No aplica a vision de producto ni convierte a Gemini en orquestador general; ChatGPT, Codex, Antigravity y usuario conservan sus roles del work-kit.
- Cualquier desviacion de patrones recomendados por Google debe quedar explicita, justificada, probada localmente cuando aplique y aceptada por Codex antes de consolidarse.

### Usuario
- fija vision
- autoriza o congela frentes
- valida alineacion comercial
- dicta el estado autoritativo cuando lo explicita

## Regla de continuidad y handoff
- El handoff debe preservar:
  - estado autoritativo actual
  - frentes congelados
  - siguiente paso correcto
  - limite de scope
- El handoff no debe arrastrar trabajo viejo que ya no sea vigente.
- Si el contexto temporal envejecio, se reemplaza antes de abrir una nueva linea de trabajo.

## Regla de no contradiccion
- Este documento no contradice las reglas inmutables.
- El contexto temporal no contradice este documento.
- Los suplementos heredados no contradicen este documento.

## Regla de foco
El work-kit existe para operar mejor, no para reabrir producto congelado.
Si una tarea intenta empujar de vuelta hacia storefront congelado, PRODUCT_SEARCH en hold, o Cesarin OS/Admin fuera de scope, el handoff correcto debe frenarlo explicitamente.
